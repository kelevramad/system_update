# Hardening 3.1 — Break up `app.py`

> **Section**: 3.1 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🟡 P2
> **Status**: Specification — not implemented

## Why

`src/system_update/app.py` is 2640 lines. It contains `SystemUpdateApp.run()` (~430 lines), all `_handle_*` methods for sub-commands, plus rendering helpers that belong elsewhere. Symptoms:

- Adding a sub-command requires editing the same file as everyone else's sub-command → constant merge conflicts.
- `run()` is impossible to read end-to-end; flow control hops between dozens of branches.
- Tests are forced to import the whole orchestration to exercise one verb.
- The dispatch logic duplicates the scanner registry (see 3.3.1).

The goal is to migrate to a **Command pattern** where each verb (`run`, `scan`, `update`, `remote`, `snapshot`, `schedule`, …) lives in its own module and `SystemUpdateApp` becomes a thin dispatcher.

## Items

### 3.1.1 — Extract `_handle_remote`

- **File**: [src/system_update/app.py:1348](../../src/system_update/app.py:1348)
- **Effort**: M (½–1 day)
- **Move to**: `src/system_update/commands/remote_cmd.py` (create new package `commands/`).
- **Plan**:
  1. Create `src/system_update/commands/__init__.py` with a base `Command` protocol or ABC: `def execute(self, args, app_ctx) -> int`.
  2. Move `_handle_remote` and any private helpers it uses into `remote_cmd.py` as `class RemoteCommand`.
  3. Replace the call site in `app.py` with `RemoteCommand().execute(args, self)`.
  4. Pass an `app_ctx` (small dataclass with cache, config, logger, executor) instead of the whole `SystemUpdateApp` — drives dependency injection and unblocks unit tests.
- **Tests**: existing remote tests should pass unchanged. Add one test that imports `RemoteCommand` directly without `SystemUpdateApp`.

### 3.1.2 — Extract `_handle_snapshot`

- **File**: [src/system_update/app.py:1627](../../src/system_update/app.py:1627)

### 3.1.3 — Extract `_handle_schedule`

- **File**: [src/system_update/app.py:1977](../../src/system_update/app.py:1977)

### 3.1.4 — Move `_render_history_html` into `report_templates.py`

- **File**: [src/system_update/app.py:2555](../../src/system_update/app.py:2555)
- **Effort**: S (≤2h)
- **Move to**: `src/system_update/report_templates.py` (already contains the rest of the templates).
- **Plan**: Pure function relocation. No state involved; purely cosmetic. Update import in `app.py` and any other caller.

### 3.1.5 — Split `SystemUpdateApp.run()` into `RunCommand`/`ScanCommand`/`UpdateCommand`

- **File**: [src/system_update/app.py:465](../../src/system_update/app.py:465)
- **Effort**: L (1–3 days)
- **Plan**:
  1. Identify the major branches inside `run()`. Likely:
     - **Scan only** (no update): goes to `ScanCommand`.
     - **Update / update-all**: `UpdateCommand`.
     - **Default interactive**: `RunCommand` (orchestrates scan → display → optional update).
  2. Create one module per command under `commands/`, each implementing `execute(args, app_ctx) -> int`.
  3. Keep shared helpers (`_apply_filters`, `_render_results`, `_emit_export`) on `app_ctx` or in a new `commands/_shared.py`.
  4. `SystemUpdateApp.run()` reduces to:
     ```python
     def run(self, args):
         ctx = self._build_context(args)
         cmd = self._dispatch(args)  # picks RunCommand/ScanCommand/UpdateCommand/...
         return cmd.execute(args, ctx)
     ```
  5. Add a single integration test per command: invoke `execute` with a minimal mocked `app_ctx` and assert exit code + a representative side effect.

## Order of operations

Land in order to keep diffs reviewable:

1. **3.1.4** first — purely mechanical move with no behavior change; warms up the pattern.
2. **3.1.1**, **3.1.2**, **3.1.3** in parallel — each is self-contained.
3. **3.1.5** last — depends on the `commands/` package and `app_ctx` shape being stable.
