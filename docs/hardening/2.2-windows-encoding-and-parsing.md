# Hardening 2.2 — Windows encoding and parsing

> **Section**: 2.2 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🟠 P1
> **Status**: Specification — not implemented

## Threat model / failure mode

These are **correctness bugs**, not security vulnerabilities, but they cause silent data loss in the inventory:

- Package names with accented characters (very common: `Microsoft Visual C++ 2015-2022 Redistributable`, vendor names in DE/PT/ES locales) get mojibake or are dropped.
- `winget upgrade` output parsed by column position breaks on every non-EN console locale and on long names.
- `datetime.fromisoformat` strips timezone, silently invalidating recently-saved cache entries.

The user-visible symptom is "the scanner sometimes misses packages I know are installed" or "the cache says it's stale even when it's not". Hard to reproduce, hard to debug — high ROI to fix.

## Items

### 2.2.1 — Subprocess encoding loses accented characters

- **File**: [src/system_update/utils.py:97](../../src/system_update/utils.py:97)
- **Effort**: M (½–1 day)
- **Problem**: `subprocess.run(..., text=True, encoding='utf-8', errors='ignore')` is called against Windows tools that emit:
  - UTF-16-LE with BOM (`reg query`, some PowerShell paths)
  - CP850 / CP1252 (legacy `cmd.exe` console)
  - UTF-8 only when the active code page is `chcp 65001`
- `errors='ignore'` swallows the bytes that don't decode, corrupting names like `Café`, `Ção`, `Software Müller`.
- **Proposed fix**:
  1. Capture stdout/stderr as **bytes** (no `text=True`, no `encoding=`).
  2. Try decoders in order: UTF-8 (with BOM strip) → UTF-16-LE (if leading `\xff\xfe`) → the active OEM code page from `ctypes.windll.kernel32.GetOEMCP()` → CP1252 → final fallback `errors='replace'` so we never crash but log a warning when we hit the fallback.
  3. Centralize this in a `decode_command_output(data: bytes) -> str` helper in `utils.py` and route every existing `subprocess.run(..., text=True)` through `subprocess.run(..., capture_output=True)` + `decode_command_output(...)`.
  4. As a second axis, opportunistically run subprocesses with `chcp 65001` set in `env`/`PYTHONIOENCODING=utf-8` for child Python processes — but do not rely on this since native tools ignore the env var.
- **Files to touch**:
  - `src/system_update/utils.py` (helper)
  - All call sites of `subprocess.run(..., text=True)` — found via:
    ```bash
    git grep -nE "subprocess\.(run|Popen).*text=True" src/
    ```
- **Tests** (`tests/test_utils.py`):
  - UTF-8 with BOM decoded correctly.
  - UTF-16-LE with BOM decoded correctly.
  - CP850 byte sequence for `é` (`\x82`) decoded correctly when `GetOEMCP()` returns 850.
  - Pure ASCII unchanged.
  - Use parametrized fixtures with raw bytes; don't rely on the host locale.
- **Acceptance criteria**:
  - [ ] `Café` and similar names round-trip from `winget list`/`reg query` into the cache without mojibake.
  - [ ] No `errors='ignore'` left in the codebase (`git grep -nE "errors\s*=\s*['\"]ignore['\"]" src/` empty).

### 2.2.2 — `winget upgrade` parser is fragile

- **File**: [src/system_update/scanners/winget.py:36](../../src/system_update/scanners/winget.py:36)
- **Effort**: M (½–1 day)
- **Problem**: Current parser locates `Id`/`Version`/`Available` column starts via `header.find('Id')`. This breaks when:
  - Console is a non-EN locale (header is e.g., `Nome  ID  Versão  Disponível  Origem` in pt-BR).
  - A `Name` value is long enough to abut `Id` with no whitespace separator.
  - Trailing column changes order across winget versions.
- **Proposed fix**:
  1. **Primary path**: invoke `winget upgrade --include-unknown --source winget --output <tempfile>` with `--format json` if winget ≥ 1.7 supports it. Detect support by parsing `winget --version`. If supported, parse JSON.
  2. **Fallback path** (older winget):
     - Read header line; locate columns by finding **runs of >= 2 spaces** as separators. This is robust against locale and long names.
     - Skip the separator line of dashes.
     - For each row, slice by the column boundaries computed from the header.
     - Compile regexes once at module level.
  3. Add a deterministic fixture `tests/fixtures/winget_upgrade_ptbr.txt` and a `_en.txt` to test both locales.
- **Files to touch**:
  - `src/system_update/scanners/winget.py`
  - `src/system_update/checkers/winget.py` (uses the same parser via shared helper if applicable)
- **Tests** (`tests/test_scanners.py`):
  - pt-BR fixture parsed correctly.
  - en-US fixture parsed correctly.
  - Long-name row (Name + Id with 1 space) still parses both fields correctly.
  - JSON path used and parsed when `winget --version` returns ≥ 1.7 (mocked).
- **Acceptance criteria**:
  - [ ] No use of `header.find('Id')` literal remains.
  - [ ] Parser works on the three fixtures above.

### 2.2.3 — `datetime.fromisoformat` drops timezone

- **File**: [src/system_update/cache.py:87](../../src/system_update/cache.py:87) and any other `fromisoformat(...replace('Z', ''))` site
- **Effort**: S (≤2h)
- **Problem**: `datetime.fromisoformat(s.replace('Z', ''))` produces a naive datetime in local time. Comparisons against `datetime.now(timezone.utc)` then yield wildly wrong deltas, so cache entries written with `Z` (UTC) appear ancient and force unnecessary refreshes — or, worse, never expire if the comparison flips sign.
- **Proposed fix**:
  1. Single helper `parse_iso_utc(s: str) -> datetime` in `utils.py`:
     ```python
     def parse_iso_utc(s: str) -> datetime:
         if s.endswith('Z'):
             s = s[:-1] + '+00:00'
         dt = datetime.fromisoformat(s)
         if dt.tzinfo is None:
             dt = dt.replace(tzinfo=timezone.utc)  # legacy entries assumed UTC
         return dt.astimezone(timezone.utc)
     ```
  2. Replace every `datetime.fromisoformat(...replace('Z', ''))` with `parse_iso_utc(...)`. Find with:
     ```bash
     git grep -nE "fromisoformat.*replace\(\s*'Z'" src/
     ```
  3. Compare against `datetime.now(timezone.utc)`. Never compare aware to naive.
- **Files to touch**:
  - `src/system_update/utils.py` (new helper)
  - `src/system_update/cache.py`
  - Any other call sites identified by the grep.
- **Tests** (`tests/test_utils.py`, `tests/test_smart_cache.py`):
  - `parse_iso_utc('2025-01-01T00:00:00Z')` → aware UTC.
  - `parse_iso_utc('2025-01-01T00:00:00+00:00')` → aware UTC.
  - `parse_iso_utc('2025-01-01T00:00:00-03:00')` → aware UTC, shifted to UTC.
  - Cache entries written with `Z` and read back compare correctly to `datetime.now(timezone.utc)`.
- **Acceptance criteria**:
  - [ ] No `fromisoformat(...replace('Z', ''))` left in `src/`.
  - [ ] Cache freshness assertions match expectations across timezone changes.
