# Hardening 1.4 — File permissions

> **Section**: 1.4 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🟠 P1 / 🟡 P2
> **Status**: Specification — not implemented

## Threat model

The CLI writes several files under `~/.system_update/` that contain or can contain sensitive data:

- `cache.json` — package inventory (machine fingerprint info)
- `vulnerability_history.json` — historical CVE data per host
- `inventory.json` — remote host names + usernames (and historically passwords)
- `snapshots.db` — pre-update package state
- `history.db` — full scan history
- `config.yaml` / `config.json` — webhook URLs, tokens (in some setups), email creds

All are written with the process default umask, which on Windows-Python translates to ACLs inherited from the parent directory — typically world-readable on a default Windows install. On a multi-user Windows host (or in a profile shared by mistake), every local user can read them.

## Items

### 1.4.1 — Apply restrictive permissions on every write

- **Files**: spread across `cache.py`, `snapshots.py`, `remote.py`, `config.py`, `history.py`
- **Effort**: S (≤2h)
- **Problem**: Files written without explicit `chmod`/ACL hardening end up readable by all local users.
- **Proposed fix**:
  1. Add a helper `secure_write(path: Path, data: bytes | str, *, mode: int = 0o600) -> None` in `src/system_update/utils.py`. Behavior:
     - POSIX: write to a temp file in the same dir, `os.chmod(tmp, mode)`, then `os.replace(tmp, path)`.
     - Windows: write via `os.replace`, then call `icacls <path> /inheritance:r /grant "%USERNAME%:(F)"` via `subprocess.run`. Wrap in `try/except` so a permissioning failure logs a warning but does not abort the write.
  2. Replace direct `path.write_text(...)` / `json.dump(open(path, 'w'))` calls in `cache.py`, `snapshots.py` (sqlite file creation), `remote.py` (inventory), `config.py` (config persist), `history.py` (history db) with `secure_write`.
  3. For SQLite (`snapshots.db`, `history.db`): after `sqlite3.connect(path)` the first time, apply the same ACL hardening to the file path.
- **Files to touch**:
  - `src/system_update/utils.py` (new helper)
  - `src/system_update/cache.py`
  - `src/system_update/snapshots.py`
  - `src/system_update/remote.py`
  - `src/system_update/config.py`
  - `src/system_update/history.py`
- **Tests** (`tests/test_utils.py`, `tests/test_security.py`):
  - On POSIX CI: `secure_write` produces a file with mode `0o600`.
  - On Windows CI (or mocked): `icacls` is invoked with `/inheritance:r` and `:(F)` for the current user.
  - Atomic rename: existing file remains intact when write fails halfway.
- **Acceptance criteria**:
  - [ ] All `~/.system_update/*` writes go through `secure_write` or an equivalent ACL-aware path.
  - [ ] No regression in cache/snapshot/history tests.

### 1.4.2 — Centralize `~/.system_update` directory creation

- **Files**: 6 modules currently call `Path.home() / '.system_update'` directly.
- **Effort**: S (≤2h)
- **Problem**: Each module re-creates the directory with default permissions. Drift is easy: one module sets `0o700`, another sets nothing.
- **Proposed fix**:
  1. Add a single `DATA_DIR` accessor in `src/system_update/config.py` (or a new `paths.py` if we want to avoid circular imports):
     ```python
     def data_dir() -> Path:
         d = Path(os.environ.get('SYSTEM_UPDATE_HOME', Path.home() / '.system_update'))
         d.mkdir(parents=True, exist_ok=True, mode=0o700)
         _harden_dir(d)  # ACL on Windows
         return d
     ```
  2. Replace every `Path.home() / '.system_update'` with `data_dir()`. Identify call sites:
     ```bash
     git grep -nE "Path\.home\(\)\s*/\s*'\.system_update'" src/
     ```
  3. The `SYSTEM_UPDATE_HOME` environment override is documented in `AGENTS.md`; preserve that behavior.
- **Files to touch**:
  - `src/system_update/config.py` (or new `paths.py`)
  - All call sites identified by the grep above.
- **Tests** (`tests/test_config.py`):
  - `data_dir()` honors `SYSTEM_UPDATE_HOME`.
  - `data_dir()` creates the directory with `0o700` on POSIX.
  - Multiple calls are idempotent.
- **Acceptance criteria**:
  - [ ] `git grep -nE "Path\.home\(\)\s*/\s*'\.system_update'" src/` returns no hits except inside `data_dir()`.
  - [ ] All previously-passing tests still pass.

## Implementation notes

- The branch `hardening/1.4-file-permissions` already exists with this spec.
- Order: land 1.4.2 first (mechanical refactor), then 1.4.1 (introduces `secure_write` and migrates writers).
- Windows ACL behavior is hard to test in cross-platform CI. Use `pytest.mark.skipif(sys.platform != 'win32')` for Windows-specific assertions and mock `icacls` in cross-platform tests.
- Run before submitting:
  ```bash
  uv run ruff check .
  uv run pytest
  ```
