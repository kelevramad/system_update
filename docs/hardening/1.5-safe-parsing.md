# Hardening 1.5 - Safe parsing

> **Section**: 1.5 of `HARDENING_PLAN.md`
> **Priority**: P2
> **Status**: Implemented

## Threat Model

Two parsing paths consume data that may be controlled by another machine or by
an untrusted report source:

- XML report handling in `export.py`.
- Remote WinRM JSON responses in `remote.py`.

## Implementation

### 1.5.1 - XML Parsing

`src/system_update/export.py` only generates XML. It does not import
`xml.etree`, `xml.dom`, `xml.sax`, `minidom`, or other XML parsers, so
`defusedxml` is not needed today. The module docstring records this assumption:
if XML import support is added later, it must use `defusedxml` and a file-size
cap before parsing untrusted input.

### 1.5.2 - Remote JSON Response Cap

Remote stdout is parsed through a shared helper that:

- Ignores non-JSON-looking stdout, preserving previous behavior.
- Rejects JSON-looking stdout larger than `remote.max_response_bytes`.
- Converts malformed JSON into a per-host error result instead of silently
  dropping the parsed payload or raising a traceback.

The default cap is `10 * 1024 * 1024` bytes. It can be overridden with
`remote.max_response_bytes` in config or
`SYSTEM_UPDATE_REMOTE__MAX_RESPONSE_BYTES`.
