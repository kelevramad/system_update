# Hardening 1.5 — Safe parsing

> **Section**: 1.5 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🟡 P2
> **Status**: Specification — not implemented

## Threat model

Two parsing paths consume data from sources we do not fully control:

1. **XML import/export** (`export.py`, feature 5.2.2). XML parsers in the Python stdlib (`xml.etree.ElementTree`, `xml.dom.minidom`, `xml.sax`) are vulnerable by default to billion-laughs, quadratic blowup, and external-entity (XXE) attacks. If a user imports a report file from an untrusted source — or the merge feature consumes a remote scan output — the process can be DoS'd or coerced into reading local files.
2. **Remote WinRM JSON responses** (`remote.py`). A compromised or impersonated remote host returns whatever JSON it likes. There is no size limit on `json.loads(stdout)`, so a multi-MB pathological payload (deeply nested arrays/objects) can spike memory and CPU on the orchestrator.

Both are realistic in scenarios where the CLI aggregates results across machines or imports user-supplied reports.

## Items

### 1.5.1 — Use defusedxml for XML parsing/generation

- **File**: [src/system_update/export.py](../../src/system_update/export.py)
- **Effort**: S (≤2h)
- **Problem**: If `export.py` imports from `xml.etree.ElementTree` or similar to **read** a report (for merge/diff), it inherits XXE/billion-laughs exposure.
- **Investigation step (must do first)**:
  ```bash
  git grep -nE "xml\.etree|xml\.dom|xml\.sax|minidom|fromstring|ElementTree" src/
  ```
  - If XML is **only generated** (write-only), no defusedxml is needed but document this in a top-of-module comment.
  - If XML is **parsed** anywhere (including merge/import paths), introduce defusedxml.
- **Proposed fix** (if parsing is present):
  1. Add `defusedxml` to `pyproject.toml`.
  2. Replace `from xml.etree import ElementTree as ET` with `from defusedxml import ElementTree as ET`. The API surface is compatible.
  3. For pure generation, keep stdlib but add a comment: `# generation only — no untrusted input parsed here`.
  4. If merge logic accepts a path argument, validate the file size before parsing (reject files > N MB; configurable, default 10 MB).
- **Files to touch**:
  - `src/system_update/export.py`
  - `pyproject.toml` (only if defusedxml added)
- **Tests** (`tests/test_export.py`):
  - XML import path rejects an XXE payload (fails closed).
  - XML import path rejects a billion-laughs payload (fails or aborts within a small timeout).
  - Round-trip export → import → export produces identical canonical output for a known-good fixture.
- **Acceptance criteria**:
  - [ ] No `xml.etree.*` import in code paths that parse external input.
  - [ ] If defusedxml is not needed, a comment documents why.

### 1.5.2 — Cap WinRM JSON response size

- **File**: [src/system_update/remote.py:253](../../src/system_update/remote.py:253)
- **Effort**: S (≤2h)
- **Problem**: `json.loads(stdout)` is called on whatever the remote process writes to stdout. No size cap, no depth limit. A hostile or broken host can return a 100 MB payload that pins the orchestrator's memory.
- **Proposed fix**:
  1. Cap stdout collection at a configurable size (`remote.max_response_bytes`, default `10 * 1024 * 1024` = 10 MB). When the cap is exceeded, abort the per-host result with a clear error: `RemoteResult(host=h, status='error', message='response exceeded 10 MiB')`.
  2. Use `json.loads` with a try/except that converts `JSONDecodeError` into the same `status='error'` instead of propagating.
  3. Optionally enforce a recursion-depth limit by parsing with a `JSONDecoder` subclass — only worth it if test fixtures show real attacks. Default off.
- **Files to touch**:
  - `src/system_update/remote.py`
  - `src/system_update/config.py` (new setting)
- **Tests** (`tests/test_remote.py`):
  - Stdout > cap → `RemoteResult.status == 'error'` with message mentioning size.
  - Malformed JSON → same error path, no traceback.
  - Normal payload (small) → unchanged behavior.
- **Acceptance criteria**:
  - [ ] No `json.loads` in `remote.py` without a preceding size check.
  - [ ] New setting documented.
