# Hardening 3.2 — Typing and contracts

> **Section**: 3.2 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🟡 P2 / 🟢 P3
> **Status**: Specification — not implemented

## Why

The CLI passes data around as `argparse.Namespace`, untyped `Dict`, and `Optional[Dict]`. Symptoms:

- Dozens of `getattr(args, 'flag', None)` defensive lookups in `app.py` and `cli.py`. Adding a flag means hunting every `getattr`.
- `RemoteResult.parsed: Optional[Dict]` — every consumer guesses the keys.
- `aggregate_scans` returns a free-form dict shaped differently depending on which sources are present.

Static checks (`mypy --strict`) cannot help today; tests cannot rely on schema invariants.

## Items

### 3.2.1 — Replace `argparse.Namespace` + `getattr` with a typed dataclass

- **Files**: [src/system_update/cli.py](../../src/system_update/cli.py), [src/system_update/app.py](../../src/system_update/app.py)
- **Effort**: L (1–3 days)
- **Plan**:
  1. Define `CLIOptions` as a `@dataclass(frozen=True)` (or `pydantic.BaseModel` if Pydantic is acceptable) in `src/system_update/cli_options.py`. One field per flag, with explicit `Optional[...]` and defaults that match argparse defaults.
  2. Add `CLIOptions.from_namespace(ns: argparse.Namespace) -> CLIOptions` that does the conversion once at the entry point. Validation goes here (mutually exclusive flags, type coercion).
  3. Refactor `SystemUpdateApp.run(args)` and every `_handle_*` to accept `opts: CLIOptions` instead of a raw namespace.
  4. Eliminate `getattr(args, ..., None)` — find with:
     ```bash
     git grep -nE "getattr\(\s*args\s*," src/
     ```
     Each becomes `opts.<field>`.
- **Tests** (`tests/test_cli_basic.py`):
  - Round-trip: `CLIOptions.from_namespace(parser.parse_args([...]))` produces expected fields.
  - Mutually exclusive flags raise at conversion time.
  - Default values match the legacy namespace behavior.
- **Acceptance criteria**:
  - [ ] `git grep -nE "getattr\(\s*args" src/` returns 0 hits.
  - [ ] mypy passes on `cli.py`, `app.py` with `--strict` (introduce in this PR or in a follow-up; document).

### 3.2.2 — Strongly type `RemoteResult.parsed`

- **File**: [src/system_update/remote.py:101](../../src/system_update/remote.py:101)
- **Effort**: M (½–1 day)
- **Plan**:
  1. Define `RemoteScanPayload` as a `TypedDict(total=False)` (preferred — interop with existing dicts) or `pydantic.BaseModel` (if Pydantic is in scope).
  2. Capture the actual schema produced by `python -m system_update --export json`:
     - `meta: {host: str, scanned_at: str, version: str}`
     - `sources: dict[str, list[PackageInfo]]`
     - `vulnerabilities: list[VulnInfo]`
     - `errors: list[str]` (new field — see 2.3.1 spec)
  3. Replace `RemoteResult.parsed: Optional[Dict]` with `Optional[RemoteScanPayload]`.
  4. Add a validator (`from_dict`) that accepts a raw `dict` from `json.loads` and either returns the typed payload or raises with a clear path-of-failure (`'sources.winget[3].id missing'`).
  5. Audit consumers: `aggregate_scans`, the HTML/CSV exporters, the UI table — they should now access fields by attribute or static key, not via `.get('foo', {}).get('bar')` chains.
- **Tests** (`tests/test_remote.py`, `tests/test_data_sharing.py`):
  - Valid payload round-trip.
  - Missing required key → clear validation error.
  - Extra keys ignored (forward compatibility).
- **Acceptance criteria**:
  - [ ] No `Optional[Dict]` in `RemoteResult`.
  - [ ] mypy clean for `remote.py`.

### 3.2.3 — Formalize `aggregate_scans` return type

- **File**: [src/system_update/remote.py](../../src/system_update/remote.py)
- **Effort**: S (≤2h)
- **Plan**:
  1. Define `AggregateReport` as a `@dataclass`:
     ```python
     @dataclass
     class AggregateReport:
         hosts: list[HostSummary]
         total_packages: int
         total_outdated: int
         total_vulnerabilities: int
         errors: list[str]
     ```
  2. Convert `aggregate_scans` to return `AggregateReport`. Update the HTML/CSV/Markdown exporters that consume it.
  3. Keep a backward-compat `to_dict()` method on the dataclass for any external consumer relying on the old shape.
- **Tests** (`tests/test_remote.py`):
  - Two-host aggregation produces the expected counts and per-host summaries.
  - Empty input → `AggregateReport(hosts=[], total_packages=0, ...)` with no errors.
- **Acceptance criteria**:
  - [ ] `aggregate_scans` is annotated `-> AggregateReport`.
  - [ ] Exporters consume the dataclass directly.

## Implementation notes

- The branch `hardening/3.2-typing-and-contracts` already exists with this spec.
- 3.2.1 is the largest mechanical change. Land 3.2.2 + 3.2.3 first if you want a faster review cadence.
- Decision: **Pydantic vs dataclasses + TypedDict**. Default to stdlib (`dataclass` + `TypedDict`) to avoid a runtime dependency; add Pydantic only if validation messages or JSON schema export are needed.
- Run before submitting:
  ```bash
  uv run ruff check .
  uv run pytest
  uv run mypy src/system_update/cli_options.py src/system_update/remote.py  # if mypy is in dev deps
  ```
