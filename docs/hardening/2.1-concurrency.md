# Hardening 2.1 — Concurrency

> **Section**: 2.1 of [HARDENING_PLAN.md](../../HARDENING_PLAN.md)
> **Priority**: 🔴 P0 / 🟠 P1
> **Status**: Specification — not implemented

## Threat model

Two concurrency bugs cause data corruption or silently neutralize parallelism:

1. **SQLite connection shared across threads** — `sqlite3.Connection` defaults to `check_same_thread=True`. Re-using one connection across threads (which the code does via a cached attribute) raises `ProgrammingError` at best and corrupts the WAL file at worst.
2. **Lock-held sleep in the rate limiter** — the per-host rate limiter holds a global lock while sleeping. Every HTTP call across every host serializes through one queue, neutralizing the worker pool.

Both look fine in single-threaded smoke tests and surface only under load.

## Items

### 2.1.1 — `sqlite3.Connection` is not thread-safe

- **File**: [src/system_update/snapshots.py:82](../../src/system_update/snapshots.py:82) (also applies to `history.py` if it uses the same pattern)
- **Effort**: M (½–1 day)
- **Problem**: `SnapshotStore` caches a single `sqlite3.Connection` (`self._conn`). Methods called from `ThreadPoolExecutor` workers (e.g., during a parallel rollback or batch snapshot operation) hit the connection from threads other than the one that opened it.
- **Symptoms**:
  - `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread.`
  - Or, if the user has set `check_same_thread=False` previously, intermittent corruption / `database is locked` errors.
- **Proposed fix**:
  1. Switch to a **per-thread connection** model using `threading.local`:
     ```python
     class SnapshotStore:
         def __init__(self, path: Path):
             self._path = path
             self._tls = threading.local()

         @property
         def _conn(self) -> sqlite3.Connection:
             c = getattr(self._tls, 'conn', None)
             if c is None:
                 c = sqlite3.connect(self._path, isolation_level=None)
                 c.execute('PRAGMA journal_mode=WAL')
                 c.execute('PRAGMA synchronous=NORMAL')
                 c.execute('PRAGMA foreign_keys=ON')
                 self._tls.conn = c
             return c
     ```
  2. Enable WAL so concurrent readers don't block a writer.
  3. Apply the same pattern to `history.py` if it uses a cached connection.
  4. Add a `close_all()` method (best-effort) for shutdown — iterate registered TLS objects via a weakref set if needed; otherwise document that connections are closed when threads terminate.
- **Files to touch**:
  - `src/system_update/snapshots.py`
  - `src/system_update/history.py` (audit; same fix if applicable)
- **Tests** (`tests/test_snapshots.py`, `tests/test_history_tracking.py`):
  - Spawn 8 threads via `ThreadPoolExecutor`, each calling write methods. No `ProgrammingError`, no lost rows, all rows present after `executor.shutdown()`.
  - WAL mode is set (read `PRAGMA journal_mode`).
  - Sequential single-thread behavior unchanged.
- **Acceptance criteria**:
  - [ ] Concurrent test passes deterministically.
  - [ ] All existing snapshot/history tests pass.
  - [ ] No `ProgrammingError` under repeated stress runs (`pytest -k snapshots --count=20` if `pytest-repeat` is available).

### 2.1.2 — `time.sleep` inside the rate-limiter lock

- **File**: [src/system_update/network.py:130](../../src/system_update/network.py:130)
- **Effort**: S (≤2h)
- **Problem**: The per-host rate limiter computes `wait` then does:
  ```python
  with _LOCK:
      ...
      time.sleep(wait)
      ...
  ```
  All HTTP callers across all hosts contend on `_LOCK` and effectively run serially during the sleep.
- **Proposed fix**:
  1. Replace the global lock with a **per-host structure** keyed by netloc:
     ```python
     class _HostLimiter:
         def __init__(self, min_interval: float):
             self.min_interval = min_interval
             self.lock = threading.Lock()
             self.last_call = 0.0
     ```
  2. Acquire the per-host lock briefly to compute `wait` and update `last_call`, then release before sleeping:
     ```python
     with limiter.lock:
         now = time.monotonic()
         wait = max(0.0, limiter.last_call + limiter.min_interval - now)
         limiter.last_call = now + wait  # reserve our slot
     if wait > 0:
         time.sleep(wait)
     ```
  3. Maintain a module-level `dict[str, _HostLimiter]` guarded by a small `_REGISTRY_LOCK`. Only the registry lookup goes through `_REGISTRY_LOCK`; per-host work uses the per-host lock.
- **Files to touch**:
  - `src/system_update/network.py`
- **Tests** (`tests/test_network.py`):
  - Two requests to **different** hosts should not serialize: total wall time ≈ max(per-host sleep), not sum.
  - Two requests to the **same** host should respect the interval.
  - Timing test uses `time.monotonic()` and a generous tolerance to stay deterministic on CI.
- **Acceptance criteria**:
  - [ ] Cross-host parallelism restored (test asserts wall-time gain).
  - [ ] Same-host rate limit unchanged.
  - [ ] No deadlocks under stress.
